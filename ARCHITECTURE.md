## 🔄 Эволюция запроса (Request Lifecycle)

```
┌─────────────────────────────────────────────────────────────────┐
│                     FRONTEND (React)                             │
│  ┌──────────────────────────────────────────────────────────┐   │
│  │  useAuth hook или fetch/axios                            │   │
│  │  Отправляет POST /api/auth с данными                    │   │
│  └──────────────────────────────────────────────────────────┘   │
└────────────────────────┬────────────────────────────────────────┘
                         │ HTTP Request
                         ↓
┌─────────────────────────────────────────────────────────────────┐
│               API ROUTE (app/api/auth/route.ts)                 │
│  Получает запрос → Парсит JSON → Вызывает контроллер           │
└────────────────────────┬────────────────────────────────────────┘
                         │
                         ↓
┌─────────────────────────────────────────────────────────────────┐
│          CONTROLLER (userController.ts)                         │
│  ┌──────────────────────────────────────────────────────────┐   │
│  │ • Проверяет action (signup/login)                        │   │
│  │ • Валидирует входные данные                              │   │
│  │ • Обрабатывает ошибки валидации                          │   │
│  │ • Вызывает нужный метод сервиса                          │   │
│  └──────────────────────────────────────────────────────────┘   │
└────────────────────────┬────────────────────────────────────────┘
                         │
                         ↓
┌─────────────────────────────────────────────────────────────────┐
│           SERVICE (userService.ts)                              │
│  ┌──────────────────────────────────────────────────────────┐   │
│  │ • Содержит бизнес-логику                                │   │
│  │ • CRUD операции: create, read, update, delete           │   │
│  │ • Проверки перед сохранением                            │   │
│  │ • Вызывает методы модели                                │   │
│  └──────────────────────────────────────────────────────────┘   │
└────────────────────────┬────────────────────────────────────────┘
                         │
                         ↓
┌─────────────────────────────────────────────────────────────────┐
│            MODEL (User.ts)                                      │
│  ┌──────────────────────────────────────────────────────────┐   │
│  │ • Mongoose схема и валидация                            │   │
│  │ • Методы для работы с коллекцией                        │   │
│  │ • Преобразование данных                                 │   │
│  └──────────────────────────────────────────────────────────┘   │
└────────────────────────┬────────────────────────────────────────┘
                         │ Query
                         ↓
        ┌────────────────────────────────┐
        │     MONGODB DATABASE 🗄️        │
        │  (Сохранение/Получение данных)│
        └────────────────────────────────┘
                         │ Response
                         ↓
┌─────────────────────────────────────────────────────────────────┐
│            SERVICE (обработка результата)                       │
└────────────────────────┬────────────────────────────────────────┘
                         │
                         ↓
┌─────────────────────────────────────────────────────────────────┐
│           CONTROLLER (формирование ответа)                      │
│  ┌──────────────────────────────────────────────────────────┐   │
│  │ {                                                        │   │
│  │   "success": true/false,                                │   │
│  │   "message": "...",                                      │   │
│  │   "data": { ... }                                        │   │
│  │ }                                                        │   │
│  └──────────────────────────────────────────────────────────┘   │
└────────────────────────┬────────────────────────────────────────┘
                         │ HTTP Response (JSON)
                         ↓
┌─────────────────────────────────────────────────────────────────┐
│                     FRONTEND (React)                             │
│  ┌──────────────────────────────────────────────────────────┐   │
│  │ useAuth обновляет state                                 │   │
│  │ Компонент перерендеривается                             │   │
│  │ Пользователь видит результат                            │   │
│  └──────────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────────┘
```

## 📊 Таблица ответственности компонентов

| Компонент | Задача | Содержит |
|-----------|--------|----------|
| **Model** | Структура данных | Schema, validation rules |
| **Service** | Бизнес-логика | CRUD методы, запросы в БД |
| **Controller** | Обработка запросов | Валидация, вызов сервисов |
| **API Route** | Маршрутизация | Обработчики GET/POST/PUT/DELETE |
| **Middleware** | Кросс-функциональность | Auth, logging, error handling |
| **Utils** | Вспомогательные функции | Валидаторы, форматеры |
| **Types** | Типизация | TypeScript интерфейсы |
| **Constants** | Значения по умолчанию | Routes, messages, roles |
| **Hooks** | Переиспользуемая логика | State management, API calls |
| **Components** | UI | React компоненты, JSX |

## 🎯 Принципы архитектуры

### 1️⃣ **Separation of Concerns**
Каждый слой имеет четкую ответственность и не смешивает логику

### 2️⃣ **Single Responsibility**
Каждый файл отвечает за одно

### 3️⃣ **Type Safety**
TypeScript типизация повсеместно

### 4️⃣ **Error Handling**
Обработка ошибок на каждом уровне

### 5️⃣ **Reusability**
Code максимально переиспользуется

### 6️⃣ **Scalability**
Легко добавлять новые ресурсы и функции

### 7️⃣ **Maintainability**
Понятная структура, документация, примеры

## 🚀 Для разработчиков

### Как я должен думать при добавлении функции?

**Question**: "Нужна функция для создания курса"

**Answer**: 
1. Добавлю модель `Course` в `models/`
2. Добавлю метод `createCourse` в `courseService`
3. Добавлю метод `create` в `courseController`
4. Добавлю route handler в `api/courses/route.ts`
5. Буду использовать на фронтенде через API запрос

**Никогда** не будешь:
❌ Писать SQL прямо в компоненте  
❌ Смешивать логику сервиса и контроллера  
❌ Забывать валидацию данных  
❌ Не обрабатывать ошибки  
❌ Оставлять magic numbers/strings
